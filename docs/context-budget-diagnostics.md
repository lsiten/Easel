# 上下文预算诊断

Easel 支持 Codex（`codex`）、OpenCode（`opencode`）、通用 ACP（`acp`）、
Pi（`pi`）以及仅聊天模式（`api`，模型 API 直连）。上下文窗口、压缩策略和工具结果裁剪
由所选底座及模型决定，不能把某个引擎的配置字段或压缩公式当成所有底座的通用规则。

## 排查上下文不足

1. 在 Web 设置中确认当前底座与模型；已有会话仍绑定原底座，切换后需新建对话。
2. 对原生底座，检查对应 CLI 的模型配置、实际请求及脱敏日志，确认模型声明的窗口、
   输出上限和原生压缩策略。仅聊天模式检查独立的 `EASEL_DIRECT_API_*` 配置与模型 API 返回的错误。
3. 区分本地底座拒绝请求与供应商拒绝请求；保存的窗口声明不等于实际模型能力，
   也不能证明运行中的会话已经加载了该配置。
4. 减少不必要的附件和重复上下文，按所选底座的原生配置方式调整预算。
   不要通过虚报模型窗口来绕过限制。

`easel doctor` 用于环境与配置检查；它不提供覆盖所有底座的上下文压缩阈值保证。
旧版专用配置的窗口换算、技能清单限额与安装器写入步骤不适用于当前底座。

## 技能与工具结果

原生 Agent 从 `skills/builtin/` 和 `skills/shared/` 按需读取技能。
技能目录、实际载入的说明与工具结果都会影响上下文开销；仅聊天模式不执行本地技能。
不要将某个底座的技能数量、字符限额或工具裁剪设置视为 Easel 的统一配置。

缓存命中与成本取决于供应商、缓存 TTL、提示前缀是否稳定及请求形态；不能仅凭窗口
大小断言缓存必然失效，或宣称调整后一定省钱。Issue #156 的表现是特定环境的实测，
不是所有后端的通用规律。
