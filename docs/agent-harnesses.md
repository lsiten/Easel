# Agent 底座接入与本地测试

Easel 将执行底座与模型供应商分开。Web 设置中的 **Agent 底座 → 执行引擎**
只提供 Codex（`codex`）、OpenCode（`opencode`）、通用 ACP（`acp`）、Pi（`pi`）
和 **仅聊天模式**（`api`，模型 API 直连）。未配置底座时使用仅聊天模式。

底座决定谁负责执行对话和工具，连接由适配器管理。原生 Agent 沿用各自 CLI 的模型供应商
与认证配置。仅聊天模式直接调用模型 API，不启动 Agent，适合问答、写作和内容分析，
不能运行本机工具或技能；API 地址、模型与 Key 单独配置。媒体通道配置独立，不随对话底座迁移。

## 接入方式

内部 `Adapter.run` 契约统一原生 Agent 的事件、问答、取消和原生会话 ID：

| 底座 | 接入方式 | 认证 | 权限 |
| --- | --- | --- | --- |
| Codex（`codex`） | `codex app-server`，私有 stdio 原生 RPC | `codex login` 或原生配置 | 默认 workspace-write；额外授权经确认，可在设置中显式开启自动授权 |
| OpenCode（`opencode`） | `opencode acp`，私有 stdio ACP v1 | `opencode auth login` | OpenCode 原生策略，ACP 权限请求交由 Web 确认 |
| 通用 ACP（`acp`） | 本机管理员配置的 argv，ACP v1 | 对应 Agent 原生登录 | 对应 Agent 原生策略，不声称提供操作系统沙箱 |
| Pi（`pi`） | `pi --mode rpc`，私有 JSONL（非 JSON-RPC）协议 | Pi 原生认证配置 | read-only / workspace-write；扩展权限请求经 Web 确认 |
| 仅聊天模式（`api`） | 模型 API 直连，无需 CLI | 独立 `EASEL_DIRECT_API_*` 配置 | 无本机工具或技能 |

Codex 使用原生协议，以保留流式事件和权限控制。ACP 是可复用适配器，供 OpenCode 与
实现 ACP 的 Agent 接入；非 ACP 底座可在 registry 中注册独立 Adapter。
原生 Agent 使用私有进程通信，不公开服务端口。

## 安装与配置

Linux / macOS：

```bash
bash setup.sh
```

Windows PowerShell：

```powershell
.\setup.ps1
```

安装器准备 Easel、Web 工作台及浏览器登录依赖。原生 Agent CLI 需在运行 Web 的同一
服务器账户下安装并完成认证；安装 Easel 不等于这些底座已经安装或认证成功。
安装后运行 `easel web`，选择已安装的底座，保存后新建对话。
尚未配置 Agent 时也可以管理账号与设置；对话需选择已认证的底座或配置仅聊天模式的模型 API。

CLI 需要在 Web 的 PATH 中。`easel web` 在非交互启动遗漏 PATH 时，会补充当前服务器账户下
常见的 npm、nvm、fnm、Volta、用户本地与 OpenCode 安装目录，包括自定义 npm 前缀、
用户 `.npmrc` 和 Windows 的 `%APPDATA%\npm`。macOS 会兼顾 Homebrew 安装路径。
只补充 Web 子进程缺失的 PATH，不覆盖已有 CLI 的优先级，不修改系统环境或任何 Agent 配置。
Windows 的 npm shim 使用 Node 或原生程序调用，不通过 shell 拼接命令。
安装后必要时重启 Web。执行引擎列表不会隐藏未检测到的底座，仍可选择查看配置及安装提示，
但未安装的底座不能保存为当前引擎。配置读取失败时可以点击「重新读取」，无需先切换底座。
自动查找限于运行 Web 的账户及已指定的安装路径，不读取其它用户的登录配置；
自定义服务账户、容器或其它目录安装仍需设置该进程的 PATH 并重启 Web。

底座、模型覆盖和权限设置保存到 `outputs/_harness/config.json`，原生认证仍由各 CLI 管理，
不复制仅聊天模式的 API 凭证。OpenCode 模型通常是 `provider/model`；模型覆盖留空时由
原生配置或模型目录解析。Pi 忽略 socks 代理，仅 http/https 代理生效。
环境变量 `EASEL_AGENT_RUNTIME` 可固定底座，此时 Web 禁止覆盖。

通用 ACP 的启动参数只能通过服务器上的 `outputs/_harness/acp.json` 配置，
Web 不提供任意命令输入。内容是 JSON argv 数组，不走 shell。例如：

```json
{"command": ["opencode", "acp"]}
```

只对可信管理员提供这个配置入口。Windows 使用可执行程序，npm 工具推荐
`node` 加原生脚本路径，而不是 `.cmd` 或 `.bat`。

## 会话与兼容性

- 切换前必须结束或停止所有运行中任务；切换后新建对话，不在已有会话中悄悄换底座。
- 原生会话 ID 与底座持久化绑定，服务重启后续接同一原生会话，不自动重试失败的原生会话为新会话。
- 浏览器 SSE 断开不取消后台 Agent；可用现有 job 回放和 last 接口取回结果。
- Web 的 Codex / OpenCode / ACP 按对话复用私有 stdio 进程，连续追问不重复握手或加载历史。
  空闲 5 分钟自动回收，最多保留 8 个空闲进程；下一轮按原生 ID 续接。
  显式停止、超时、协议错误、配置变更、删除对话和服务关闭回收相应进程。
  CLI 单次执行仍在结束后回收进程。
- 删除 Easel 的对话绑定不会删除 Codex / ACP 的原生历史。
- 内置技能统一存于 `skills/builtin/`，跨技能共享层为 `skills/shared/`；原生底座直接读取这些目录。
  Web 启动 Agent 的 cwd 固定为实际安装的 Easel 根目录，不接受用户传入工作目录。
  共享身份、业务规则和人格说明位于 `agents/workspace/`，不绑定某个引擎。
  Codex 通过 `developerInstructions`，OpenCode / ACP / Pi 通过消息前缀加载共享说明，
  再追加当前引擎与运行时路径。仅聊天模式不能声明已经加载或执行本地技能。
- Web 展示的聊天记录保存在当前浏览器本地，原生上下文按服务器持久化的会话 ID 续接；
  清空浏览器数据或换浏览器不等同于迁移聊天记录。
- ACP 不声明客户端文件 / terminal 能力，因此依赖客户端代执行这些工具的 Agent 暂不支持；
  需要 Agent 自带工具。协议版本必须是 ACP v1；历史续接要求 `loadSession`。
- “CLI 已安装”不是认证成功或模型在线的证明；用实际消息或 `easel ping` 验证。
- `easel chat`、`easel skill`、`easel ping` 使用所选底座；仅聊天模式不支持执行技能。

## 原生客户端交互并发上限

Easel 默认不增加工具调用次数或任务总运行时间预算。这不改变底座既有超时、权限或
协议资源保护。

Codex / ACP 的每条原生连接最多保留 64 个尚未完成的客户端请求（例如权限确认）。
收到超限请求时，本轮以明确错误结束并关闭连接，清理待处理交互；会话池不会复用此连接。
完成的请求会释放名额，不累计计入后续批次。此限制不自动重试或重新发送原始提示词。
它是协议资源保护，不是工具调用预算，也不证明外部工具副作用已经撤销。

## 验收建议

### API 配置与模型选择

- 选择仅聊天模式后配置模型 API；原生底座使用各自 CLI 的认证与模型设置。
- Codex、Pi 和 OpenCode 的“模型覆盖”提供下拉框，点击“拉取模型”才启动原生 CLI
  读取列表，不创建对话，也不在打开设置时自动读取。Codex 使用 `model/list`，
  OpenCode 使用 `opencode models`，Pi 使用 `get_available_models`；列表不代表每个模型都已授权可用。
- 也可手动填写模型 ID。读取列表失败时保留原有模型设置，保存后新建对话。

1. 对每个已安装并认证的底座，新建对话让它仅回复一段文字。
2. 同一对话再问上一轮内容，刷新页面 / 重启 Web 后再续接。
3. 对原生底座，让它读取公开技能说明，再生成小文件到 `outputs/`，确认真实工具执行。
4. 对实际出现的额外权限请求分别拒绝、允许一次；不要使用发布等不可逆动作做初测。
5. 点击停止，确认可立即再发消息；检查断线回放和错误提示。
6. 切换到另一个已配置底座并新建对话，再返回原有对话验证会话归属与续接。
7. 仅聊天模式只验证模型 API 对话，不把文字中的执行声明当作本地工具运行结果。

各底座的专属工具与供应商设置不保证完全等价。原生 CLI 和协议更新后应重新运行
协议测试、完整 Python 测试与前端构建。
