# 循环保护诊断

Codex（`codex`）、OpenCode（`opencode`）、通用 ACP（`acp`）和 Pi（`pi`）
使用各自原生的工具执行与保护策略。仅聊天模式（`api`，模型 API 直连）不执行本机工具，
因此没有本地工具循环。

Easel 默认不增加工具调用次数或任务总运行时间预算；底座已有超时、权限控制及
客户端协议资源限制仍然生效。`easel doctor` 的环境检查不证明某个底座启用了循环检测，
旧版专用的循环保护配置字段与 Agent 覆盖计数不适用于当前底座。

排查重复工具调用时，先确认会话绑定的底座与模型，再查看对应原生 CLI 的配置和脱敏日志。
已保存的开关不证明运行中的会话已加载，也不证明每个检测器都已启用；
实际配置与行为以该底座的原生能力为准。

循环检测不是严格的每任务调用预算。预算需要实际工具执行前的拦截、任务作用域和并发计数，
不能拿 HTTP 请求次数代替工具调用数，也不能认为停止任务会撤销已执行的副作用。
